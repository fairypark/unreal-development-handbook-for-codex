# 환경 제작 요구사항 대화 — 한국어 검토본

영문 원문: Chapter 04의 [Collaborative requirements dialogue](04-world-level-design.md#collaborative-requirements-dialogue), Chapter 15의 [Requirements elicitation and direction-setting](../../guide-unreal-ai-development/references/15-ai-assisted-development.md#requirements-elicitation-and-direction-setting).

## 목적과 적용 범위

새 환경, 넓은 재설계, 시각 품질 수리에서 경험이나 화면의 중요한 방향이 미정일 때, 사용자가 원하는 결과를 구체화하도록 돕는다. 환경 아트 전문 용어나 완성된 명세서를 요구하지 않는다. 이미 승인된 국소 수정은 기존 브리프를 계승하고, 해당 수정의 범위나 결과를 바꾸는 미정 사항만 질문한다.

요청, 승인된 참고 자료, 기존 브리프와 관련 증거에서 이미 확정된 내용을 먼저 추출한다. 확정한 결정, 제안한 방향, 되돌릴 수 있는 가정, 미정인 결정을 구분한다. 이미 제공한 정보를 다시 묻거나, 사용자의 명시적인 취향을 AI의 취향으로 대체하거나, 참고 이미지의 모든 사물과 보이지 않는 뒷면까지 승인된 요구사항으로 간주하지 않는다.

## 질문을 고르는 방법

현재 결정에 영향이 큰 질문을 소수씩 묶어 묻고, 답변에 따라 다음 질문을 조정한다. 아래 항목 전체를 필수 설문으로 제시하지 않는다. 수치나 구현 방법을 묻기 전에 화면 또는 플레이에서 어떤 차이가 생기는지 설명한다.

| 필요할 때 구체화할 결정 | 사용자에게 할 질문 | 함께 설명할 방향 |
| --- | --- | --- |
| 경험과 정서 | 이 장소에 들어오면 플레이어가 무엇을 느끼고 어떤 행동을 하길 원하나요? | 차분하게 전망을 발견하는 길, 노출되어 긴장되는 통과 구간, 보호된 모임 장소. 동선과 가시성의 차이를 설명한다. |
| 참고 자료의 권한 | 참고 자료에서 구도, 재질, 식생, 분위기, 주인공 중 무엇이 가장 중요한가요? 피하고 싶은 인상은 무엇인가요? | 주 품질 목표, 보조 참고 자료, 금지할 인상을 구분한다. 충돌하는 요구를 조용히 평균 내지 않는다. |
| 시점과 주인공 | 어느 진입 또는 플레이 시점에서 무엇이 가장 먼저 눈에 들어와야 하나요? | 실루엣이 열린 랜드마크, 전경 사이로 차츰 드러나는 주인공, 넓은 파노라마. 실제 플레이 카메라의 검증 권한을 유지한다. |
| 밀도와 생태 | 길을 식생이 감싸는 느낌인가요, 열린 공간에 군집이 놓이는 느낌인가요? 어디를 비워 두고 싶나요? | 빈틈이 분명한 조밀한 군집, 여러 층의 가장자리 식생, 관리된 정원. 생태층과 빈 공간을 주인공에 연결한다. |
| 지면과 접촉 | 길은 닳은 흙, 느슨한 자갈, 젖은 돌 또는 다른 표면 중 무엇으로 읽혀야 하나요? 가까이서 중요한 접촉부는 어디인가요? | 재질의 크기, 가장자리 전이, 뿌리, 낙엽과 지지 관계를 설명한다. 재질 이름 선택에 그치지 않는다. |
| 에셋 적합성과 제어 | 특정 형태를 재현해야 하나요, 가용 에셋에 맞춰 방향을 조정해도 되나요? 직접 구성해서 유지할 부분은 어디인가요? | 키트 조정, 직접 조립한 주인공, 반복 가능한 절차적 구역. 소유 확인, 가용성, 대표 검증을 구분한다. |
| 범위와 완료 | 이번 목표는 콘셉트, 플레이 가능한 블록아웃, 대표 시각 구간, 넓은 프로덕션 작업 중 무엇인가요? 고정된 제약은 무엇인가요? | 해당 범위의 증거와 비용을 설명한다. 이미 정한 플랫폼, 일정, 에셋, 성능 제약을 재사용한다. |

## 사용자가 아직 방향을 고르기 어려울 때

구체적인 대안을 소수 제시하고 하나를 추천한다. 추천 이유는 사용자가 밝힌 의도, 실제 증거, 에셋 적합성에 연결한다. 각 대안의 화면 또는 플레이 결과, 주요 장단점, 이를 확인할 관찰을 설명한다. 참고 이미지의 부분 비교, 도식, 작은 비교 콘셉트가 판단에 도움이 되면 사용하고 필요한 한국어 검토본을 제공한다. 확인하지 않은 구현 적합성은 미확인으로 표시한다. 상세한 프롬프트, 매력적인 콘셉트, 추천 옵션을 구현 완료나 승인으로 간주하지 않는다.

사용자의 답을 기존 브리프의 관찰 가능한 목표로 옮긴다. 의도한 인상, 대상 시점 또는 동선, 우선순위, 보호할 요구, 적용 증거, 남은 불확실성을 적는다. 예를 들어 “자연스러운 식생”은 “바위와 나무 그늘 주변의 불규칙한 군집, 읽기 쉬운 길, 랜드마크를 향해 의도적으로 열린 공간”으로 구체화할 수 있다. 수치 범위는 이후 실제 크기, 참고 자료, 대표 실험에서 도출한다. 화면이나 경험의 의도를 이해하기 전에 임의의 정밀 수치를 만들지 않는다.

## 미정 사항과 권한

빠진 결정이 승인된 설계, 수정 권한, 필수 단계 증거를 실질적으로 바꾸면 그 결정에 의존하는 작업을 대기시키고, 영향받지 않는 승인된 작업만 계속한다. 선택적인 취향은 되돌릴 수 있는 가정이나 기본안을 명시하고 기존 권한 안에서 진행할 수 있다. 답변이 없다는 이유로 승인 처리하지 않는다. 사용자가 일상적인 선택을 위임했다면 이유를 설명하고 판단하며 같은 허락을 반복해서 묻지 않는다. 새 증거나 의도 변경으로 전제가 무효화될 때만 기존 결정을 다시 연다.

## 대화의 완료 기준과 AI 책임

사용자가 자신의 의도를 알아볼 수 있는 브리프와 다음 결정 또는 승인된 실험이 남아야 한다. 현재 단계 기록을 재사용하며 질문마다 새 승인 게이트나 별도 산출물을 만들지 않는다. 선택한 방향에 관찰 가능한 수용 기준이 있고, 제안·가정·미확인 증거가 확정 사실로 바뀌지 않았는지 확인한다.

이 원칙은 AI가 다른 Unreal 작업의 요구사항을 구체화할 때에도 적용한다. 구현 파라미터나 도구를 먼저 고르게 하지 않고 결과와 장단점부터 설명한다. 질문은 의도를 명확히 하는 과정이며, 설계·수정·증거·독립 승격 계약을 대체하지 않는다.
