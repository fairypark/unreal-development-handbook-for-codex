# 핸드북이 판단을 개선하는지 평가하기 — 한국어 검토본

대응 원문: [Judgment evaluation](judgment-evaluation.md), [평가용 구성 사례](judgment-scenarios.v1.json).

## 주장과 증거를 구분한다

| 주장 | 필요한 증거 | 그것만으로 입증하지 못하는 것 |
| --- | --- | --- |
| 교육 자료의 구조가 올바르다 | 링크·대조 사례·실행 가능한 연습·기존 계약·회귀 검사 | 원인을 이해하거나 더 나은 결정을 했는지 |
| 새로운 맥락에 판단을 전이한다 | 같은 조건의 응답 비교·맥락 변경 문제·중립적인 이유와 시험 선택 평가 | 실제 Unreal 결과나 제작 준비도 |
| 선택이 실제 결과를 개선한다 | 목적에 맞는 시제품·제작 실험의 플레이어·시각·기술·복구 증거 | 모든 프로젝트에서의 우월성이나 통제 없는 단일 원인 귀속 |

이 평가는 새 제작 승인 단계가 아니다. 집필 개편과 학습 효과를 평가할 때 사용하며 작은 지역 작업마다 의식적으로 강제하지 않는다.

## 연습 자료와 미공개 전이 평가

공개 연습 자료는 조건을 바꾸어 판단해 보는 7쌍, 총 14문제로 구성했다. 이동 방식과 목적지 간격, 게임 상태의 소유자, 화면 문제의 원인, GPU와 CPU 병목, 배포 범위, 변경 전후 비교, 저장 파일 호환성을 다룬다. 마지막 두 문제에서는 이전 버전이 최신 저장 파일을 읽을 수 있는지만 달라진다. 그 차이가 복구 방법을 어떻게 바꾸는지, 각 방법에서 플레이어의 진행도를 어떻게 확인할지 생각해 본다.

핸드북 옆에 공개돼 있으므로 이 자료를 비공개·처음 보는 문제로 학습 효과를 입증했다고 설명하면 안 된다. 검토 근거는 평가자에게 두고 준비 스크립트는 질문과 중립 응답 요청만 내보낸다. 진짜 전이 시험에는 교육 자료를 고정한 뒤 별도의 미공개 문제를 작성한다. 사적 프로젝트 정보·자격 증명·사용자 대화 원문은 넣지 않는다.

## 비교 절차

1. 후보·비교 핸드북 버전, 문제, 평가 차원, 자원 예산, 모델·참여자 설정, 평가자 지침을 고정하고 기타 맥락 차이를 기록한다.
2. 같은 조건에서 후보 자료 유무 또는 개편 전후의 응답을 받는다. 이전 답이 비교에 새지 않도록 세션을 분리한다. 모델 교체 효과를 핸드북 개편 효과와 혼동하지 않는다.
3. 중요한 결정과 이유, 대안과 비용, 선택을 바꾸는 조건, 최소 구분 시험, 권한 한계를 묻는다. 문제를 놓친 장황한 절차보다 짧고 타당한 설명을 높게 본다.
4. 가능한 경우 답 순서를 섞고 버전 이름을 가린다. 원 응답과 판정 이유를 보존한다. 원하는 결론을 미리 주거나 작성자가 실패 판정을 통과로 바꾸게 하지 않는다.
5. 맥락 변경 쌍과 낯선 문제를 함께 본다. 변경된 조건이 관련 없다는 근거가 충분하면 같은 선택도 가능하다. 무조건 답을 뒤집는 것이 목표가 아니다.
6. 개선과 실패, 표본 수, 비용, 불확실성, 보정 연습인지 미공개 전이 시험인지를 보고한다. 신뢰할 개선 주장에 독립 검토가 필요하면 사용하고, 자기 점검만 했다면 명시한다.

## 평가 차원

탐색적 교육 검토는 각 차원을 0–2로 평가할 수 있다. 0은 누락·중대한 오류, 1은 가능하지만 불완전, 2는 증거와 맥락에 구체적으로 맞는 설명이다. 기존 시각 제작 점수나 새 승격 기준이 아니다.

- 의도와 실패 규모: 미충족 결과와 판단의 규모를 찾는가.
- 원인 추론: 관찰·가능한 작동 관계·경쟁 설명·불확실성을 연결하는가.
- 대안과 트레이드오프: 실행 가능한 다른 선택의 비용·한계를 비교하는가.
- 맥락 전이: 조건에 따라 판단을 바꾸거나 바꿀 필요 없는 이유를 설명하는가.
- 구분 가능한 검증: 권고를 반박할 수 있는 적절한 비용의 관찰을 제안하는가.
- 범위와 권한: 안전·소유·증거 한계·사용자의 실제 승인을 지키는가.

원칙 이름 인용·체크리스트 반복·에이전트 수·서류 수에 점수를 주지 않는다. 자유 답변을 단순 키워드로 채점하지 않는다. 여러 설계가 타당할 수 있다. 결과 날조·중대한 실패 은폐·무단 파괴는 평균 속에 숨기지 않고 실패로 기록한다.

## 실행과 보고 한계

저장소 루트에서 `python scripts/prepare_judgment_exercise.py --language ko --output .tmp/judgment-questions.ko.json`을 실행하면 한국어 질문의 순서를 섞은 파일이 생긴다. 참여자에게는 이 파일을 주고 평가자용 해설은 별도로 보관한다. 답변과 실제 제작 결과는 각각 따로 평가한다.

구조 검사는 자료 완전성·답안 분리·문서 연결을 확인하며 AI 행동 시험이 아니다. 비교 가능한 응답과 평가가 없으면 **판단 개선: 미입증**, 실제 프로젝트 시험이 없으면 **제작 결과 개선: 미입증**으로 보고한다.
