# v0.2.9 — Concept-led asset readiness before level dressing

This release adds a staged content-supply contract between approved environment
concepts and level dressing. It makes asset demand, ownership, acquisition
authority, licensing, dependencies, representative proof, and production
approval inspectable without forcing final-asset acquisition before cheap
experience prototypes and blockouts.

## Included

- Added Stage 2b **Concept-to-Asset Readiness** after the existing Stage 2a
  reference translation, with independent `ASSET_PLAN_READY`,
  `VISUAL_SLICE_READY`, and `PRODUCTION_DRESSING_READY` locks.
- Expanded Content & Asset Architecture to derive functional asset-family
  demand from approved source requirements and zones, search project-native and
  ownership-confirmed content first, and give every gap an explicit reuse,
  acquisition, authoring, procedural, outsourcing, substitution, or concept
  revision route.
- Separated discovery, entitlement, acquisition to staging, representative
  approval, and production approval so a listing, remembered purchase,
  download, or Visual Slice cannot silently authorize map-wide dressing.
- Added license, compatibility, dependency, integration-cost, family
  completeness, ordinary-repetition, transition, reverse-side, contact,
  performance, cook, maintenance, and rollback checks for exact candidate
  versions.
- Added a machine-readable Concept-to-Asset Readiness JSON Schema, locked
  starter template, semantic validator, and regression tests.
- Routed owned Fab discovery through `fab-library-advisor` when available while
  keeping purchase, download, install, migration, plugin enablement,
  outsourcing, and upload as separately authorized actions.
- Preserved the v0.2.8 `BOUNDED_PROTO_EDIT` fast path and made asset-family,
  acquisition, license, or dependency changes explicit exits to the full staged
  workflow.

## Validation

- Handbook test suite: 34 tests passed.
- Reference-to-Prototype and Concept-to-Asset Readiness templates: valid.
- Official Plugin validator passed.
- Official validators passed for all five changed Handbook Skills.
- Configured secret guard and `git diff --check` passed.
- No Unreal project, level, Editor state, marketplace account, purchase,
  download, migration, or Editor/MCP API was changed by this Handbook release.

This release changes Handbook reasoning, plugin routing, and validation
contracts only. Asset acquisition and live Editor execution remain separately
authorized operations, and no readiness gate by itself grants transaction or
mutation authority.
