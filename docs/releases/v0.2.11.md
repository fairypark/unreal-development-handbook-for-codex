# v0.2.11 — Terrain representation and production target contracts

This release adds the approved Handbook improvements for terrain
representation, bidirectional procedural data flow, reference-grounded AI
work, and architecture-specific production targets. It keeps the Handbook
focused on durable reasoning rather than Editor operation or API instructions.

## Included

- Added a blocking Chapter 04 **Terrain Representation Review** before broad
  Landscape application when the actual engine/build/project context supports
  Mesh Terrain. The review compares topology, streaming, collision/navigation,
  PCG, target budgets, maturity, fallback, rollback, and owner decision.
- Preserved Landscape as the default when Mesh Terrain is unsupported or
  unsuitable, while requiring a user or designated approver to decide after a
  supported Mesh Terrain comparison is explained.
- Added a Chapter 09 bidirectional terrain/PCG data-flow contract with
  immutable source revisions, separate query/write layers, aligned priority
  and sub-priority, source-position preservation, feedback-loop protection,
  idempotence, persistence, runtime, performance, and rollback checks.
- Added Chapter 15 reference-grounded context handling for complex procedural
  work, including bounded structured context, plan-before-mutation,
  incremental supervision, and reviewer questions.
- Expanded Chapters 11 and 13 target identity beyond platform names to include
  runtime and authoring/build-host architecture, toolchain, SDK/GDK, plugin or
  middleware ABI, and architecture-specific fallback. Recorded the dated UE
  5.8 Windows ARM64/ARM64EC game-target limitations.
- Added regression coverage for the new canonical guidance and Skill routing.
