# v0.2.8 — Bounded prototype edit fast path

This release adds a scope-matched fast operation for small changes to an
already accepted Unreal prototype. It reduces unnecessary broad gates and
round trips without promoting the level or weakening Landscape, zone-marker,
bridge, route, grounding, or staged-workflow safety rules.

## Included

- Added the explicit `BOUNDED_PROTO_EDIT` entry and exit contract for named
  prototype Transform/scale changes and named existing-Actor deletion.
- Added a recommended 120-second wall-clock target, one-level/eight-Actor
  default bound, target allowlist, protected snapshot, rollback, and fail-closed
  exit rules.
- Defined the compact transaction order:
  `inspect → mutate → in-memory verify → save → persistence re-read`.
- Separated `operation_verdict` from `promotion_verdict`; visual capture, PIE,
  independent review, and broad plan/translation review can remain
  `NOT_RUN_BY_CONTRACT` when outside scope.
- Required target-specific four-corner grounding for bounded building moves and
  automatic exit for direct Landscape, water, bridge, zone-marker,
  route/navigation, streaming, camera, or other plan-owned changes.
- Added automation guidance for task-scoped schema caching, compact responses,
  capture separation, and explicit optional/default/required/unknown field
  handling.
- Added an anonymized case-study note and regression coverage for the fast path.

## Validation

- Handbook test suite: 23 tests passed.
- Reference-to-Prototype contract template: valid.
- `git diff --check` passed with only existing line-ending normalization
  warnings.
- No CodexMiniArena level, Unreal Editor state, or Editor/MCP API was changed
  by this Handbook release.

This release changes Handbook reasoning and validation contracts only. A live
Editor execution layer must implement the batch transport and response
semantics separately, and a bounded operation does not constitute level or
production promotion.
