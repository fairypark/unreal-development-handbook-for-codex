# v0.2.19 — UE5_9 프리뷰 프로젝트 실측

UE 5.8의 초지·PCG 사례를 보존하고 Windows의 UE 5.9.0 CL 60351404에서 여섯 가지 도입 질문을 직접 시험했습니다. [한국어 검증 기록](https://github.com/fairypark/unreal-development-handbook-for-codex/blob/v0.2.19/skills/validate-unreal-production/references/ue-5-9-preview.ko.md) · [English project results](https://github.com/fairypark/unreal-development-handbook-for-codex/blob/v0.2.19/skills/validate-unreal-production/references/13-production-pipeline.md#ue-59-megajam-preview)

- **MCP와 Blueprint** — GameMode 복제본 편집·컴파일·저장 뒤 새 프로세스에서 해당 함수가 복제본에만 남았음을 확인했습니다.
- **Mesh Terrain과 PCG** — 두 층의 충돌, 아래층 보행, 네 PCG 점의 위·아래 투영을 확인했습니다. Paint 클릭 후 0.015초에는 입력점만 늘었고, 0.281초에는 나무도 늘었습니다. 재생성 및 다시 열기 후 두 배치가 유지됐습니다.
- **Lumen과 Nanite** — World Cache 패스와 GPU 시간을 기록했습니다. Nanite를 적용한 나무 71개의 생성 수는 같았습니다. 식생 구간은 대조군의 프레임 시간 차이가 커서 성능 우열을 판정하지 않았습니다.
- **웹 저장** — Chrome 157에서 기본 Wasm 패키지가 새로고침 후 슬롯을 잃는 현상을 재현했습니다. Epic의 프로젝트 경로 인자를 적용하자 체크포인트가 복원됐고 보상 재청구는 0개였습니다.
- **AI 뷰포트** — 게임 원본과 Canvas 원본 스트림을 확보했습니다. 동일 게임 카메라의 AI 가공 결과는 미확인입니다.

핸드북 단위 테스트 59개, 플러그인과 스킬 9개, 계약 예제 2개, 상대 링크 및 비밀정보 검사를 통과했습니다. 검증한 운영체제·GPU·브라우저와 미검증 범위는 본문에 기록했습니다. [핸드북 소스 ZIP](https://github.com/fairypark/unreal-development-handbook-for-codex/archive/refs/tags/v0.2.19.zip)
